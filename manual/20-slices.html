Slices

A slice is a non-owning reference to a contiguous sequence of elements. It borrows storage owned elsewhere and never allocates or deallocates its own elements.

Type Syntax

Slice types use the ref keyword with a sequence type:

ref T[]
ref mut T[]

Examples:

ref byte[]
ref mut int[]

The ref keyword distinguishes a slice view from an owning T[] array value.

Slice Values

A slice contains conceptual runtime information equivalent to:

  • data address
  • length

The representation is compiler-defined and is not an FFI-stable struct layout. A slice contains no capacity and no allocator identity.

A slice inherits storage origin and lifetime from its source. A slice never owns or deallocates its elements.

Owning Dynamic Array Type

T[] is a valid owning value type and may appear in storage positions such as struct fields, variables, parameters, and return types:

let values: byte[]
type Lexer struct {
    input: rune[],
}

The length is runtime-known rather than part of the nominal type identity.

Rule: ref T[] references a type, not storage. It must be applied to an actual value: ref buffer[..].

Slice Creation

A slice is created explicitly with ref or ref mut:

// Complete array
let view := ref values[..]

// Mutable complete array
let writable := ref mut values[..]

// Subrange
let middle := ref values[1..<4]
let inclusive := ref values[1..3]

Slice creation does not copy elements and does not allocate backing storage. Only the small reference descriptor is produced.

Rule: There is no implicit array-to-slice conversion. Use explicit source syntax: Process(ref values[..]).

Slice Ranges

Slice ranges use the existing range operators:

Exclusive upper bound:

source[start..

Inclusive upper bound:

source[start..end]   // indexes: start through end

Open bounds are allowed:

source[..]       // complete sequence
source[start..]  // start through final element
source[..end]    // first element through end, inclusive
source[..

Descending slice ranges are invalid. A slice range does not reverse a sequence. Empty slices are valid through an exclusive range.

Rule: Range endpoints must use valid integer index types. Negative endpoints are invalid.

Slicing a Slice

A slice may be sliced again:

// Shared reborrow
let part := ref view[2..<5]

// Mutable reborrow
let part := ref mut writable[2..<5]

A mutable reborrow requires a ref mut T[] source. A shared reborrow may be created from either shared or mutable source access, subject to borrow rules.

The resulting slice lifetime cannot exceed the source slice lifetime or the ultimate storage owner lifetime.

Length

Slices expose .len:

let sliceLength := view.len

The type of len is uint. It is read-only. No capacity member exists for slices.

Copy and Move

Slice classification:

  • ref T[] — copyable shared reference descriptor. Copying copies only the descriptor, never elements.
  • ref mut T[] — move-only exclusive reference descriptor. Must not be freely copied because that would duplicate exclusive access. May be moved or safely reborrowed.

Destruction

A slice is trivially destructible. Destroying a slice:

  • does not destroy elements
  • does not release backing storage
  • does not reset an arena
  • does not affect the owner except by ending the borrow

Null and Empty Slices

A safe slice is never null. There is no null slice value.

An empty slice is valid, but it must still originate from valid storage or a compiler-defined empty-storage sentinel that obeys reference rules.

Rule: A slice has no implicit default value because a reference must have a valid origin. Consequently a mutable safe-slice declaration cannot omit its initializer.

Function Parameters

Examples:

fn Sum(values: ref int[]) int
fn Clear(values: ref mut byte[]) void
fn Consume(values: int[4]) void

A by-value array parameter follows normal copy or move rules. A slice parameter borrows the source. Explicit slice creation is required initially.

Returning Slices

Borrowing

Basic array and slice implementation must record:

  • storage owner or origin
  • shared or mutable reference mode
  • element type
  • slice length
  • source range when statically known

The compiler must immediately reject obvious lifetime errors such as returning a slice into a local array.

Equality

Slices do not support == or != in the initial implementation. Slice equality is ambiguous between reference identity and content equality. Content comparison may later be provided by an explicit function or method.

FFI

Slices must not cross an FFI boundary directly. A wrapper must pass explicit foreign-compatible components such as RawPtr[T] and uint. Ownership, nullability, and lifetime remain explicit at the FFI boundary.
