# Correction 16 — struct field-tag parsing is not quote-aware

## Audit context

- Repository: `github.com/YoePro/sec`
- Repository baseline: `c515862`
- Audited: `2026-08-19`
- Primary rulebook: `rules/declarations/struct.md`
- Document revision: **2.0**
- Created: `2026-08-13`
- Last updated: `2026-08-13`

## Classification

Implementation bug.

This is not a language-rule change.

Revision 2.0 defines struct field tags as raw-string metadata containing one or
more Go-inspired entries of the form:

```text
key:"value" key:"value"
```

and requires malformed tag syntax to produce a compile-time diagnostic.

The current parser does not parse that grammar. It splits the raw tag with
`strings.Fields()` and then only checks that each resulting substring contains a
colon and that the value begins and ends with `"`. This makes parsing depend on
whitespace inside quoted values and accepts malformed quote structure.

The root governance ledger currently marks raw-string field tags as parsed and
preserved open-key metadata without recording this limitation.

---

## Normative requirements

`rules/declarations/struct.md` revision 2.0 states:

- tags use `key:"value" key:"value"` form;
- multiple entries may occur in one raw tag literal;
- the compiler must not hard-code a closed key list;
- malformed tag syntax is a compile-time diagnostic;
- parsed metadata must be preserved for consumers.

The quoted value is one syntactic unit. Whitespace that occurs inside the quoted
value is not an entry separator merely because the outer tag contains spaces.

Likewise, quote characters must be structurally valid rather than accepted only
because the first and final byte happen to be quotes.

---

# Bug 1 — whitespace inside a quoted tag value is treated as an entry separator

## Affected code

`internal/parser/parser.go`

Current implementation:

```go
func (p *Parser) parseStructTag(token lexer.Token) ([]ast.StructTag, bool) {
    raw := strings.TrimPrefix(strings.TrimSuffix(token.Lexeme, "`"), "`")
    if strings.TrimSpace(raw) == "" {
        return nil, true
    }

    tags := []ast.StructTag{}
    for _, part := range strings.Fields(raw) {
        key, value, ok := strings.Cut(part, ":")
        if !ok || key == "" || len(value) < 2 ||
           value[0] != '"' || value[len(value)-1] != '"' {
            p.addError("invalid struct field tag")
            return nil, false
        }
        tags = append(tags, ast.StructTag{
            Key:   key,
            Value: strings.Trim(value, `"`),
        })
    }
    return tags, true
}
```

`strings.Fields()` has no knowledge of quoted regions.

Therefore a tag such as:

```sec
type Item struct {
    Label: string `ui:"hello world"`,
}
```

is split approximately into:

```text
ui:"hello
world"
```

and rejected.

The source still matches the canonical `key:"value"` shape: the whitespace is
inside the quoted value, not between tag entries.

A real tag parser must distinguish those two cases.

---

# Bug 2 — malformed internal quote structure can be accepted

The parser validates only:

```text
value[0] == '"'
value[last] == '"'
```

It does not parse the quoted value itself.

For example, malformed source of the conceptual form:

```sec
type Item struct {
    ID: int `json:""id""`,
}
```

can pass the current first/last-character test as one field.

Then:

```go
strings.Trim(value, `"`)
```

removes the extra leading/trailing quote characters and silently normalizes the
malformed source to a semantic value resembling:

```text
id
```

Similarly, malformed unescaped quote structure inside the value can be retained
rather than diagnosed if the first and final bytes still happen to be quotes.

Revision 2.0 requires malformed tag syntax to be rejected, not repaired by
trimming quote runs.

---

# Bug 3 — parser recovery aborts the remaining struct field list after an invalid tag

When `parseStructTag()` fails, `parseStructFields()` currently does:

```go
if !ok {
    for p.peekToken.Type != lexer.RBRACE &&
        p.peekToken.Type != lexer.EOF {
        p.nextToken()
    }
    return fields
}
```

Thus one malformed field tag skips to the struct's closing brace and prevents
later fields from being parsed.

The same rulebook requires malformed struct fields to recover at a field/list
boundary without cascading into unrelated failures.

An invalid tag is a malformed part of one field; it should not normally erase
the rest of the declaration from the AST.

This recovery issue is related to the tag parser defect and should be corrected
with it.

# Required correction

## 1. Implement a quote-aware tag scanner/parser

Parse the raw content left-to-right.

At minimum the parser must recognize:

```text
entry      := key ":" quoted-value
tag-list   := entry (whitespace+ entry)*
```

where separator whitespace is recognized only outside a quoted value.

Do not use `strings.Fields()` to tokenize the grammar.

## 2. Validate the key and quoted value structurally

The parser must detect at least:

- missing key;
- missing colon;
- missing opening quote;
- unterminated quoted value;
- unexpected characters after a quoted value before the next valid separator;
- malformed quote/escape structure according to the canonical quoted-value
  syntax.

Do not accept malformed values merely because their first and last byte are
quotes.

## 3. Preserve the semantic value without destructive quote trimming

Do not use:

```go
strings.Trim(value, `"`)
```

because it removes an arbitrary run of quote characters.

Remove exactly the one syntactic opening and closing delimiter after successful
parsing, and process any canonical escape syntax exactly once if the tag grammar
defines escapes.

If tag values are intentionally raw-within-raw and do not process escapes, make
that rule explicit and preserve their content accordingly.

## 4. Preserve open-key behavior

Do not introduce a key allowlist.

These must remain ordinary metadata keys:

```text
json
xml
db
yaml
csv
custom
vendor_specific
...
```

The correction concerns syntax, not key policy.

## 5. Recover at the current field/list boundary

On an invalid tag:

- emit one focused tag diagnostic;
- synchronize to the comma or closing brace belonging to the current field;
- continue parsing subsequent fields when recovery is unambiguous.

Do not skip every later field merely because one tag is malformed.

## 6. Preserve tag order and metadata

Multiple tag entries must remain in source order in AST/Sema metadata.

The fix must not change nominal type identity, field type, ownership,
defaultability, equality, or destruction semantics merely because a tag exists.

```

Narrow this until corrected.

Suggested wording:

the current parser handles simple whitespace-free quoted values but quote-aware
tag grammar and malformed-tag recovery remain partial
```

The existing remaining item:

```text

ownership, cleanup, FFI, and end-to-end tests
```

is too broad to document that the supposedly implemented tag parser accepts and
rejects the wrong syntax. Add the limitation explicitly.

# Required regression tests

Add tests covering at least:

## Valid tags

1. one simple tag entry;
2. multiple entries separated by spaces;
3. arbitrary/open custom key;
4. empty quoted value;
5. quoted value containing an ordinary space;
6. quoted value containing multiple whitespace characters if permitted by the
   canonical quoted-value grammar;
7. multiple entries where one value contains whitespace;
8. tag order preserved in AST and Sema.

## Invalid tags

9. missing key;
10. missing colon;
11. missing opening quote;
12. missing closing quote;
13. extra unescaped quote structure such as `key:""value""`;
14. unexpected text after the closing quote;
15. malformed escape sequence if escapes are part of the canonical grammar;
16. malformed tag emits a focused diagnostic.

## Recovery

17. malformed tag on the first field does not prevent a later valid field from
    being parsed;
18. malformed tag in the middle of a struct recovers at the field/list boundary;
19. later duplicate/unknown-field diagnostics remain available after recovery;
20. malformed tag does not cause unrelated expression-parser cascades.

## Applied

Applied on 2026-08-23 to `rules/declarations/struct.md`,
`internal/parser/parser.go`, focused parser tests, and
`implementation-status.yaml`. Tag scanning is quote-aware, preserves inner
whitespace and escape spelling, validates quote structure, and recovers at the
current field boundary.
