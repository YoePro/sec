# Correction 29 — Arena value traits, ArenaDomain identity, and borrowed-backing lifetime are not preserved by the current frontend

## Audit context

- Repository: `github.com/YoePro/sec`
- Repository baseline: `c515862`
- Audited: `2026-08-20`
- Primary rulebook: `rules/memory/arena.md`
- Status: **canonical Arena rulebook for Sec 0.1**
- Explicit document revision metadata: **not present**
- Generation: current canonical Arena design; do not infer generation from missing revision metadata
- Related rulebooks:
  - `rules/memory/allocation.txt`
  - `rules/memory/reference_model.md`
  - `rules/memory/borrowing.txt`
  - `rules/memory/lifetime_analysis.txt`
  - `rules/memory/destruction.txt`
  - `rules/memory/copy_move.md`

## Classification

This correction contains three concrete software bugs, governance reconciliation,
and one direct rulebook consistency defect:

1. builtin `Arena` is currently classified as copyable and trivially
   destructible even though the canonical rule says it is move-only and has
   terminal destruction semantics;
2. Arena-backed reference epochs are keyed by the current owner variable name
   rather than a stable `ArenaDomain` identity, so moving the Arena owner breaks
   Reset invalidation;
3. `Arena.FromBuffer()` validates the argument type but does not preserve the
   exclusive backing borrow for the Arena lifetime;
4. the final canonical summary incorrectly mixes fixed/growable policy with
   backing-ownership kinds.

The Reset/Release live-dependency legality issue is already tracked separately by
`correction28.md` and is not duplicated here.

---

# Bug 1 — builtin `Arena` is classified as trivially copyable

## Canonical rule

`arena.md` states:

```text
Arena is move-only and non-copyable.
```

A move:

```sec
let second :<- first
```

transfers the one Arena owner.

After the move:

```text
second owns the same ArenaDomain;
first is moved-from and cannot be used.
```

A type containing an Arena is move-only by composition.

---

## Current builtin representation

`internal/sema/types.go` registers:

```go
"Arena": {Name: "Arena", Kind: StructType},
```

All builtins are then marked:

```go
typ.Intrinsic = true
```

However `copyClassificationOf()` does not use `Intrinsic` to classify Arena.

For `StructType`, the compiler has a special move-only list:

```go
case "Task",
     "Thread",
     "MutexGuard",
     "Subscription",
     "Channel",
     "Sender",
     "Receiver",
     "MessageTicket":
    return CopyMoveOnly
```

`Arena` is absent.

The generic struct path then collects stored fields:

```go
fields := make([]Type, 0, len(typ.Fields))
...
return aggregateCopyClassification(fields, visiting)
```

Builtin Arena has no ordinary stored fields in this semantic skeleton.

The aggregate of zero fields is therefore:

```text
CopyTrivial
```

---

## Consequence

The generic ownership layer can treat Arena as an ordinary copyable value.

That directly contradicts the canonical ownership rule.

It also means a containing user struct may fail to become move-only by
composition, because the Arena field contributes `CopyTrivial` rather than
`CopyMoveOnly`.

This is more specific than the governance statement that "complete ownership and
move tracking" remains unfinished: the current type trait actively reports the
wrong answer for the fundamental Arena type.

---

# Bug 2 — builtin `Arena` is classified as trivially destructible

## Canonical rule

`arena.md` states:

```text
When a still-owned Arena reaches its normal destruction boundary,
Arena destruction performs terminal Release semantics.
```

This applies to normal scope/function/field/task/thread cleanup.

Release may:

- terminate the ArenaDomain;
- return owned backing;
- end borrowed backing access;
- invoke target/provider cleanup.

Arena destruction is therefore semantically non-trivial.

---

## Current implementation

`TriviallyDestructible()` sends StructType through generic field recursion:

```go
case StructType:
    ...
    for _, field := range typ.Fields {
        if !triviallyDestructible(field.Type, visiting) {
            return false
        }
    }
    return true
```

Again, builtin Arena has no ordinary fields in the semantic skeleton.

Therefore:

```text
TriviallyDestructible(Arena) == true
```

at baseline `c515862`.

This is wrong independently of whether physical lowering exists.

Semantic destruction classification must encode the terminal Arena Release
obligation before lowering.

---

## Required correction for Arena traits

Arena needs explicit compiler-owned value traits.

At minimum:

```text
CopyClassification(Arena) = MoveOnly
TriviallyDestructible(Arena) = false
EqualityComparable(Arena) = false
Defaultable(Arena) = false unless a separate canonical rule explicitly defines
                     a meaningful default Arena
```

Do not infer these properties from the empty StructType skeleton.

Prefer a compiler-known/intrinsic trait registry rather than scattered type-name
switches where practical.

A struct containing Arena must derive:

```text
move-only
non-trivial destruction
```

through ordinary composition.

# Bug 3 — Arena epoch identity is keyed by owner variable name instead of stable ArenaDomain identity

## Canonical rule

The canonical model separates:

```text
Arena owner value
ArenaDomain identity
validity epoch
physical backing
```

Moving the Arena owner:

```sec
let second :<- first
```

does **not** create a new ArenaDomain and does **not** invalidate existing
Arena-backed references.

Existing references remain attached to the same ArenaDomain/epoch.

A later:

```sec
second.Reset()
```

advances the same ArenaDomain epoch and invalidates all ordinary references from
the old epoch, including references created while the owner was named `first`.

---

## Current reference metadata

`Arena.New` and `Arena.Alloc` build references using:

```go
ReferenceOriginName: receiver.Value,
ReferenceOriginGeneration:
    a.arenaGenerations[receiver.Value],
```

The logical origin identity is therefore the lexical identifier used as receiver.

Reset performs:

```go
a.arenaGenerations[receiver.Value]++
```

Stale-reference checking performs:

```go
current :=
    a.arenaGenerations[symbol.Type.ReferenceOriginName]
```

So both epoch ownership and reference identity are keyed by variable names.

There is no `ArenaDomain` semantic identity in `Type`, `Symbol`, or the relevant
Analyzer state.

---

## Observable failure after Arena move

Conceptually:

```sec
let mut first := try Arena.WithCapacity(1024)
let value := try first.New[int]()

let mut second :<- first

second.Reset()

Use(value)
```

Canonical semantics:

1. `first` owns ArenaDomain D, epoch G;
2. `value` depends on D/G;
3. the move transfers ownership of D/G to `second`;
4. the move itself leaves `value` valid;
5. `second.Reset()` advances D to G+1;
6. `Use(value)` is invalid/stale.

Current name-keyed representation can instead do:

```text
value.ReferenceOriginName = "first"
arenaGenerations["first"] = G

move first -> second
    no ArenaDomain transfer fact exists

second.Reset()
    arenaGenerations["second"] = G+1

Use(value)
    looks up arenaGenerations["first"] == G
    concludes value is still current
```

Thus a legal owner move can disconnect old references from later Reset
invalidation.

This violates one of the central reasons the rulebook introduced ArenaDomain as
an identity independent of the owner variable.

---

## Required correction for ArenaDomain identity

### 1. Introduce stable compiler-owned ArenaDomain IDs

Every Arena creation must produce a semantic identity such as:

```text
ArenaDomainID
```

The exact representation is implementation-defined.

It must not be the lexical variable name.

Creation sites include:

- `Arena.FromBuffer`;
- `Arena.WithCapacity`;
- `Arena.Growable`;
- compiler-managed Arena creation.

### 2. Carry domain identity through owner moves

Moving Arena owner state transfers:

```text
ArenaDomainID
current epoch
backing policy
Arena state version / ownership authority
```

to the destination owner.

The source owner becomes unavailable.

References remain associated with the same `ArenaDomainID`.

### 3. Key epoch state by ArenaDomainID

Replace conceptual state:

```text
arenaGenerations[variableName]
```

with domain-owned state:

```text
arenaEpoch[domainID]
```

or equivalent SSA semantic facts.

A Reset through any current owner of the domain then invalidates every
reference associated with that domain's prior epoch.

### 4. Keep diagnostics source-friendly

Diagnostics may still display the current or original Arena binding name.

Human-readable naming is not semantic identity.

Store source provenance separately from `ArenaDomainID`.

# Bug 4 — `Arena.FromBuffer()` does not retain the exclusive backing borrow

## Canonical rule

`Arena.FromBuffer(ref mut buffer)`:

```text
takes an exclusive borrow of the supplied mutable view;
keeps the backing owner outside the Arena;
requires the supplied view to remain valid for the complete Arena lifetime.
```

While the Arena is live:

```text
conflicting direct use of the backing view is invalid.
```

On Release/destruction:

```text
the exclusive borrow ends;
direct use of the backing may become valid again.
```

Nested Arena semantics rely on the same dependency relationship.

---

## Current constructor analysis

`inferArenaConstructorCall()` validates only the argument type:

```go
if argumentType.Kind != ReferenceType ||
   !argumentType.ReferenceMutable ||
   argumentType.Element == nil ||
   argumentType.Element.Kind != SliceType ||
   ...
{
    error
}
```

It then records:

```go
ArenaEffectCreateBorrowed
```

and returns plain builtin `Arena`.

It does not attach the backing reference origin to the created Arena value.

---

## Why ordinary `ref mut` handling does not preserve the Arena lifetime borrow

`inferRefExpression()` checks whether a mutable borrow **may be created**, but
the actual borrow holder is registered when a reference value is stored or
transferred through `bindBorrowHoldersFromExpression()`.

For a direct initializer such as:

```sec
let r := ref mut buffer
```

the initializer is a `RefExpression`, so the holder can be registered.

For:

```sec
let mut arena := Arena.FromBuffer(ref mut buffer)
```

the initializer is a `CallExpression`.

`bindBorrowHoldersFromExpression()` only turns a CallExpression into a retained
borrow when:

```go
a.expressionReferenceOrigins[expr]
```

contains returned reference-origin information.

`inferArenaConstructorCall()` publishes no such backing-origin/dependency fact.

The resulting Arena type is also not a reference type and carries no backing
dependency field.

Therefore the exclusive `buffer` borrow is not tied to the Arena holder's
lifetime.

---

## Observable failure

Conceptually invalid:

```sec
let mut arena := Arena.FromBuffer(ref mut buffer)

Write(buffer)     // must conflict with Arena's exclusive backing borrow

arena.Release()

Write(buffer)     // may be valid after Release
```

Current constructor recognition can accept the Arena without registering a
borrow whose holder is `arena`.

That means ordinary borrow checks have no record preventing direct backing
access during the Arena lifetime.

---

## Required correction for borrowed backing

A borrowed Arena must retain explicit semantic backing metadata:

```text
ArenaDomainID
BackingKind = Borrowed
backing Place/reference origin
exclusive mutable borrow
borrow owner = Arena owner state/domain
lifetime = until Release/destruction/move transfer
```

Moving the Arena owner transfers the backing-borrow responsibility with the
ArenaDomain.

Reset must **not** end this backing borrow.

Release/destruction must end it.

The borrow must participate in:

- direct read/write conflict checking;
- moving the backing owner;
- nested Arena creation;
- return/escape analysis;
- defer/destruction ordering;
- task/thread transfer;
- Semantic IR.

Do not encode this only as an `ArenaEffectCreateBorrowed` call-graph event.
An effect site does not enforce aliasing/lifetime.

# Rulebook defect — final summary conflates backing kind with fixed/growable Arena policy

Earlier in `arena.md`, backing ownership kind is explicitly defined as one of:

```text
Owned
Borrowed
Static
TargetProvided
```

Separately, the rulebook defines:

```text
Fixed Arena
Growable Arena
```

as capacity/growth policy.

However the final canonical summary says:

```text
Backing may be owned, borrowed, static, target-provided, fixed, or growable.
```

That sentence mixes two independent axes.

`fixed` and `growable` are not backing ownership kinds under the same book's
earlier taxonomy.

## Required wording correction

Prefer:

```text
Backing may be owned, borrowed, static, or target-provided.

Independently, an Arena may be fixed or growable according to its capacity and
growth policy.
```

This is a direct internal rulebook consistency fix.

## ArenaDomain identity through move

9. create Arena-backed ref through owner `first`;
10. move Arena owner from `first` to `second`;
11. reference remains valid immediately after the move;
12. `second.Reset()` invalidates the pre-move reference;
13. `second.Release()` terminates the same domain;
14. moving Arena multiple times preserves one stable domain identity;
15. references allocated both before and after an owner move share the correct
    domain and current epoch;
16. diagnostic display may mention source/current owner names without using them
    as semantic identity.

## Borrowed backing

17. `Arena.FromBuffer(ref mut buffer)` creates an exclusive backing borrow;
18. direct read/write conflicting with that borrow is rejected while Arena lives;
19. moving the backing owner is rejected while the Arena lives;
20. Arena.Reset retains the backing borrow;
21. Arena.Release ends the backing borrow;
22. implicit Arena destruction ends the backing borrow;
23. moving the Arena transfers the borrow-holder responsibility;
24. nested Arena from parent allocation blocks conflicting parent storage use as
    required;
25. returning/escaping borrowed Arena cannot outlive its backing.

## Governance and documentation

## Applied 2026-08-23

Arena is now move-only and non-trivially destructible in frontend traits. Arena
creation assigns stable domain identity that survives owner moves, and borrowed
Arena backing is held exclusively through moves and Reset until explicit Release.
Implicit destruction, escape, nested-Arena, and task integration remain tracked
as partial in `implementation-status.yaml`. The canonical summary now separates
backing ownership kind from fixed/growable capacity policy.
