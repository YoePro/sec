Interfaces

An interface defines a named contract that types may implement. It describes required members and associated declarations without specifying how those members are implemented.

Interfaces enable polymorphism through explicit conformance. A type declares which interfaces it implements, and the compiler validates that all required members are present with compatible signatures.

Declaring an Interface

An interface declaration uses the interface keyword:

interface Vehicle {
    fn Start() void
    fn Stop() void
}

An interface declaration creates a named type. The interface name follows normal naming rules and uses uppercase, consistent with other nominal types.

Rule: Interfaces are declared with interface Name { ... }. The old syntax type Name interface { ... } is not part of the current language.

Interface Members

An interface may contain the following member types:

  • Methods — function signatures that implementing types must provide.
  • Properties — property declarations with required accessors (get, set).
  • Variables — mutable or immutable member declarations.
  • Constants — named constant declarations.
  • Enums — nested enum declarations.
  • Named types — nested type aliases or new type declarations.
  • Nested interfaces — interfaces declared inside other interfaces.

Interface members define requirements unless the language explicitly permits an implementation body.

Methods

A required method has no body. It declares the signature that implementing types must match:

interface Reader {
    fn Read(buffer: ref mut [byte]) Result[int, IOError]
}

The compiler validates:

  • member name
  • parameter count and order
  • parameter types and ownership
  • parameter mutability
  • receiver type and mutability
  • return type
  • generic parameters
  • unsafe requirements
  • error type compatibility

A method with a different signature does not satisfy the interface.

Properties

An interface may require properties with specific accessors:

interface Named {
    property Name: string {
        get
    }
}

interface MutableNamed {
    property Name: string {
        get
        set
    }
}

A property requiring only get may be implemented by a property that provides both get and set. A property requiring set must provide a compatible setter. Property types must match exactly.

Variables and Constants

An interface may require variables:

interface Positioned {
    mut Position: Point
}

A required variable declares the member name, type, and mutability expected from the implementing type. A mutable interface variable cannot be satisfied by an immutable member.

An interface may require constants:

interface Limited {
    const MaximumSize: int
}

A required constant must be available through the implementing type with a matching type. Its value may differ between implementing types unless the interface specifies a required value.

Associated Declarations

Enums and named types declared inside an interface belong to the interface namespace:

interface Connection {
    enum State {
        Closed
        Connecting
        Open
    }

    type Identifier uint64
}

They are accessed through the interface name:

let state: Connection.State
let id: Connection.Identifier

Associated declarations are defined by the interface itself and are not redeclared by each implementing type unless explicitly required.

Implementing an Interface

A type declares implemented interfaces in its type declaration using the implements keyword:

type Car struct implements Vehicle {
    engine: Engine
}

The implementation is explicit. Sec does not use structural or implicit interface implementation.

Rule: A type implements only the interfaces explicitly listed in its declaration. There is no duck typing or structural conformance.

Required members are implemented in the type's ordinary impl block:

impl Car {
    fn Start() void {
        // ...
    }

    fn Stop() void {
        // ...
    }
}

Multiple Interfaces

A type may implement multiple interfaces:

type Car struct implements Vehicle, Serializable, Inspectable {
    engine: Engine
}

Duplicate interface names are invalid.

Implementation Validation

The compiler validates that:

  • every named interface exists
  • every implemented target is an interface
  • implemented interfaces are not duplicated
  • all required members are present
  • all member signatures are compatible
  • required variables and constants exist
  • property accessors are compatible
  • inherited interface requirements are satisfied
  • generic arguments are valid
  • visibility is sufficient
  • no inheritance cycle exists

Conformance is checked after the type and its ordinary impl members have been collected. Member declaration order must not affect validation.

Generic Interfaces

Interfaces may have generic parameters:

interface Collection[T] {
    property Length: uint {
        get
    }

    fn Get(index: uint) ref T
}

A type specifies the complete interface type it implements:

type Names struct implements Collection[string] {
    values: []string
}

Interface Constraints

Interfaces may be used as generic constraints:

fn Print[T implements Printable](value: ref T) void {
    value.Print()
}

A type satisfies the constraint only when it explicitly declares the interface.

Interface Inheritance

An interface may extend one or more interfaces:

interface ReadWriter implements Reader, Writer {
}

An implementing type must satisfy all inherited members. Cycles in interface inheritance are invalid. Duplicate inherited members are allowed only when their declarations are compatible.

Interface Values

An interface may be used as a value type:

fn StartVehicle(vehicle: ref Vehicle) void {
    vehicle.Start()
}

The interface value preserves the concrete target, the implemented interface, ownership or reference mode, and dynamic dispatch information. Using an interface must not erase ownership, mutability, or lifetime rules.

Ownership and Interfaces

Declaring an interface does not define ownership. Ownership is determined by how the interface is used:

fn Inspect(vehicle: ref Vehicle) void       // shared borrowing
fn Update(vehicle: ref mut Vehicle) void    // mutable borrowing
fn Store(vehicle: Vehicle) void             // ownership

An owning erased interface value is move-only unless independent copy semantics are known.

Visibility

An interface must be visible wherever it is named in implements. Members used to satisfy a visible interface must have sufficient visibility for calls through that interface. Private helper members do not affect interface conformance.

Restrictions

An interface must not:

  • contain ordinary executable statements
  • contain unnamed declarations
  • implicitly apply to a type
  • add stored fields to an implementing type
  • override ownership rules
  • bypass visibility rules
  • bypass unsafe requirements

Interface declarations are compile-time constructs. Interface values may require runtime representation for dynamic dispatch, but the representation is chosen by the compiler and must not change interface semantics.

Complete Example

interface Vehicle {
    fn Start() void
    fn Stop() void

    property IsRunning: bool {
        get
    }
}

type Car struct implements Vehicle {
    engine: Engine
    running: bool
}

impl Car {
    fn Start() void {
        engine.Start()
        running = true
    }

    fn Stop() void {
        engine.Stop()
        running = false
    }

    property IsRunning: bool {
        get {
            return running
        }
    }
}

fn Drive(vehicle: ref Vehicle) void {
    vehicle.Start()
    // ...
    vehicle.Stop()
}
