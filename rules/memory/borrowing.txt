Borrowing
=========

Borrowing provides temporary access to an owned value without transferring ownership.

Borrowing is validated entirely at compile time.

The compiler must track borrows for:

* local variables
* function parameters
* return values
* struct fields
* array elements
* slice elements
* union payloads
* captured values
* values referenced by defer blocks

## Borrow kinds

Sec supports two borrow kinds:

* shared borrow through ref
* exclusive mutable borrow through ref mut

A shared borrow permits read access.

An exclusive mutable borrow permits read and write access.

## Borrow compatibility

Any number of shared borrows may coexist for the same value.

A mutable borrow requires exclusive access.

A mutable borrow may not coexist with:

* another mutable borrow
* any shared borrow of the same value
* direct mutation through the owner
* operations that may invalidate the borrowed location

While a shared borrow exists, the borrowed value may not be mutated.

While a mutable borrow exists, the owner may not be accessed directly except through that mutable borrow.

## Borrow duration

Borrow duration is determined by static analysis.

The initial implementation may use lexical scopes.

The compiler may later shorten a borrow to its final use when this can be proven safely.

The programmer must not provide explicit lifetime annotations.

A borrow ends when:

* its reference leaves scope
* ownership of the reference ends
* the compiler proves that the reference is no longer used

The compiler must account for control-flow paths when determining borrow duration.

## Branches

Borrow state must be tracked separately for each branch.

At a branch merge, the compiler must conservatively merge borrow state.

A borrow that may remain active on any incoming branch must be treated as active after the merge.

The compiler must reject branch-dependent borrow states that cannot be merged safely.

## Loops

Borrow state must be valid across every loop iteration.

A borrow created during one iteration must not conflict with access in a later iteration.

A reference must not escape an iteration when the referenced value may be invalidated before the next use.

Mutable collection iteration must prevent structural mutation of the iterated collection.

Structural mutation includes operations that may:

* change collection length
* move collection storage
* invalidate element addresses
* reorder elements when references remain active

Mutation of an element through the iterator-provided reference is permitted when the iterator provides ref mut access.

## Fields and disjoint locations

The compiler should distinguish independent fields when it can prove that they do not overlap.

Borrowing separate fields of the same struct may be permitted.

Example:

type Pair struct {
Left: int
Right: int
}

let left := ref mut pair.Left
let right := ref mut pair.Right

This is valid if the compiler proves that Left and Right are disjoint.

Borrowing an entire value conflicts with borrowing any field of that value.

Index-based disjointness is not assumed unless proven.

Two runtime indexes into the same collection must be treated as potentially overlapping.

The current frontend canonicalizes locally bound reference aliases back to
their referent Place. Reborrows through distinct struct fields or distinct
constant array indices may coexist; equal paths and dynamic indices overlap.
The granting borrow held by the alias is treated as the permission used for an
access through that alias, while direct owner access remains blocked.

## Function calls

Borrow rules apply to function arguments and method receivers.

A parameter of type ref T creates or propagates a shared borrow.

A parameter of type ref mut T creates or propagates an exclusive mutable borrow.

The callee may not retain a reference beyond the lifetime permitted by the function signature and ownership rules.

A function call must not receive overlapping mutable references.

The compiler must reject calls where arguments may alias incompatibly.

For an extern parameter, `ref T` and `ref mut T` specialize these same rules to
a non-null call-bounded foreign borrow. The foreign implementation must not
retain the address. Raw foreign reference returns and stored foreign pointer
fields do not use safe references; they use `RawPtr[T]` and wrappers establish
any safe lifetime separately.

## Closure captures

Closures may explicitly capture shared and mutable borrows:

```sec
capture(ref value) fn() int { return value }
capture(ref mut value) fn() void { value += 1 }
```

The closure may not outlive the captured borrow. A mutable capture reserves
exclusive authority for the lifetime of that capture and blocks conflicting
outer access. A closure containing `ref mut` capture is move-only and requires
at least mutable callable capability. Normal borrow/lifetime analysis proves
validity without new source lifetime syntax.

## Returning references

A returned reference must originate from a valid external owner.

A reference to a local value may not be returned.

A returned reference must follow the reference-origin rules defined in references.txt.

Borrows created inside a function end when the function returns unless the returned reference explicitly propagates an allowed input reference.

## Moves and borrowing

A borrowed value may not be moved while the borrow is active.

A field may not be moved while the containing object or overlapping field is borrowed.

A reference itself may be moved according to its type semantics without moving the referenced value.

## Defer

A defer block may extend the effective use of captured values until function exit.

The compiler must treat every value read or referenced by defer as used at the point where the defer block executes.

A value may not be moved, destroyed or invalidated before a registered defer block has finished using it.

## Borrow diagnostics

Borrow diagnostics must identify:

* the conflicting access
* the original borrow
* the location where the borrow remains active
* the reason the accesses conflict

The compiler should suggest a narrower scope or reordered operation when applicable.

Borrowing must not require runtime borrow counters, runtime locks or garbage collection.

=====================================================================
Current Implementation Status
=====================================================================

Implemented:

* `ref` parameters are parsed and represented as reference types in semantic
  analysis.
* `ref mut` parameters are parsed and represented distinctly from `ref`.
* Function signatures include reference mutability through the resolved
  parameter type.
* Calls to `ref` and `ref mut` parameters may currently borrow compatible
  values implicitly.
* Semantic analysis tracks active borrows as structured places rooted in local
  symbols.
* Place projections currently cover fields, properties, constant and dynamic
  indexes, slices, and implicit dereference through references.
* Multiple shared borrows of overlapping places may coexist.
* `ref mut` requires exclusive access to overlapping places.
* Creating `ref mut` while a shared or mutable borrow exists is rejected.
* Creating `ref` while a mutable borrow exists is rejected.
* Direct reads through the owner are rejected while an active `ref mut` borrow
  of the same root exists.
* Direct assignment to the owner is rejected while an active shared or mutable
  borrow of the same root exists.
* A mutable reference to an immutable owner is rejected.
* Borrow holders are tracked for local reference variables.
* Borrow holders are tracked for `ref` and `ref mut` values stored directly
  inside local aggregate initializers.
* Reassigning a reference variable ends the borrow previously held by that
  variable.
* Moving a move-only reference variable transfers the borrow holder to the new
  variable.
* Moving a move-only aggregate value transfers any borrows held by references
  inside that aggregate.
* Passing a move-only reference to a by-value function parameter consumes the
  local holder; the original reference variable becomes moved and cannot be
  reused.
* Passing a move-only aggregate to a by-value function parameter consumes the
  aggregate holder and ends borrows held by that aggregate.
* Moving a move-only root symbol is rejected while that symbol is actively
  borrowed.
* Borrows held by variables declared inside a block are ended when that block
  finishes.
* Active borrows are conservatively merged across continuing `if`, `switch`,
  `select` and statement-`match` branches.
* Borrow holders declared outside a branch keep their borrow active after the
  branch if any continuing path assigns them a borrow.
* Branch-local borrow holders still end at block exit before branch borrow
  state is merged.
* `for` and `while` loop headers join active borrows from loop entry, normal
  body fallthrough and every recorded `continue` edge. The joined state is
  checked against the next condition and body iteration.
* Loop exits conservatively join entry, fallthrough, `continue` and explicit
  `break` borrow states, so a borrow retained by an outer holder remains active
  after the loop whenever any exit path may retain it.
* Fresh `for` bindings and borrow holders declared inside a loop body are
  removed at their iteration boundary rather than leaking into the next
  iteration.
* Conflicts caused by a borrow that may survive a back-edge are diagnosed as
  previous-iteration conflicts and retain the originating borrow location.
* Reference-origin joins retain up to 16 distinct canonical Places. Reborrows
  through such a finite set project, register and check every possible referent
  rather than collapsing immediately to one root or requiring runtime tags.
* Missing or over-limit provenance remains conservative and cannot be
  reborrowed as though one canonical origin had been proven.
* Values used by defer blocks are tracked as delayed root-symbol uses, so a
  later move or discard is rejected while ordinary mutation remains permitted.
* A reference binding used by defer cannot be moved before the defer executes;
  this keeps the borrow held by an immutable reference binding active.
* Separate struct fields and distinct compile-time constant array indices are
  recognized as disjoint.
* Dynamic indices conservatively overlap other indices under the same base.
* Statically known inclusive, exclusive and open slice bounds are normalized to
  half-open intervals. Disjoint intervals and constant indices outside an
  interval do not conflict; empty intervals borrow no elements.
* Constant indexes and subranges through local slice aliases compose with the
  source interval, while dynamic bounds remain conservative.
* Borrowing a complete place conflicts with borrowing any of its projections.
* Field/index reads and assignments use place overlap instead of only the root
  symbol.
* Borrow creation rejects temporary and non-addressable expressions.
* Moving a nested struct field checks only borrows overlapping that field;
  borrowing the complete root still conflicts with every field move.
* Moving a move-only union payload through pattern binding checks the
  variant-payload Place against active borrows of the payload or whole subject.
* Different union variant payload projections are structurally disjoint.
* `Variant(ref name)` and `Variant(ref mut name)` borrow the active payload
  Place for named unions and Result `Ok`/`Err` variants. Mutable bindings require
  a mutable reusable subject and conflict with overlapping owner borrows.
* Payload pattern borrows end at arm exit. Their references cannot escape via a
  match value, an outer assignment, returned aggregate or captured lambda.

Not implemented yet:

* symbolic/runtime slice-range disjointness beyond statically known bounds
* borrowed payload destructuring beyond one positional payload binding
* returned-reference origin analysis
* complete place-sensitive borrow effects and explicit owned/moved capture
  modes for defer
* diagnostics that point to both the original borrow and conflicting access

Initial limitation:

Place overlap is structural and conservative. Static slice intervals and
constant indices are separated when disjoint; runtime indices and symbolic
slice bounds overlap unless their disjointness is proven. Properties overlap
their receiver because setter effects are not yet summarized.
