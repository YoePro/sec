=============================================================================================================================================================================================
References
=============================================================================================================================================================================================

References provide temporary access to an existing value without transferring ownership.

References never own memory.

Reference validity is determined entirely at compile time.

The lifetime of a reference may never exceed the lifetime of its owner.

Sec provides two reference kinds:

- ref
- ref mut

ref provides immutable access.

Multiple immutable references may coexist.

ref mut provides exclusive mutable access.

A mutable reference grants temporary write access without transferring ownership.

The compiler is responsible for verifying reference validity.

References may be created only from valid owned values or from other valid references where permitted.

Returning a reference is permitted only when the compiler can prove that the referenced object remains valid after the function returns.

Returning references to local variables is always invalid.

Returning references that may originate from multiple unrelated owners is invalid.

Reference creation shall never allocate memory.

References shall never extend object lifetime.

References shall never imply ownership transfer.

References into generation-based storage, such as arena-backed storage, carry a
semantic generation dependency.

This dependency is used by the compiler to reject stale references after an
operation such as arena reset. It does not require a runtime reference object.

Conceptually, a reference may be associated with:

- storage origin
- owner or region identity
- generation or epoch
- mutability
- lifetime boundary

Using a reference whose generation is known to be stale is invalid.

Reference equality compares the referenced object rather than ownership.

References participate in normal type checking.

Implicit conversion between references and raw pointers is forbidden.

Explicit conversion to RawPtr is permitted only within unsafe contexts.

Explicit conversion from RawPtr to references requires compiler validation or an explicit unsafe operation.

References may be passed through function parameters.

Reference mutability forms part of the function signature.

The compiler may temporarily create internal references during semantic analysis, but such implementation details are not visible in the language.

References are implemented identically for hosted and embedded targets.

The exact borrowing rules governing simultaneous references are defined in borrowing.txt.

=====================================================================
Current Implementation Status
=====================================================================

Implemented:

- semantic reference types carry origin metadata
- origin metadata records the source symbol name
- origin metadata records the source token for diagnostics
- origin metadata records whether the source is local function storage
- origin metadata records the source storage origin where known
- `ref value` attaches origin metadata from `value`
- reference origin propagates through local reference variables
- explicitly typed reference variables preserve origin from their initializer
- returning `ref` to a local function binding is rejected
- returning a local reference variable whose origin is local is rejected
- `Ok(ref local)` is rejected for `Result[ref T, E]`
- returning a reference parameter is allowed because the origin is caller-owned
- returning aggregate literals containing references to local function storage is
  rejected
- returning a lambda that captures a reference whose origin is local function
  storage is rejected
- field and index access propagate reference-origin metadata when the accessed
  value is itself a reference
- slices carry reference-origin metadata from the sliced source
- local reference and slice bindings retain a canonical structured Place for
  their referent; reborrows through fields and constant/dynamic indices are
  checked against the original storage path
- moving a mutable reference binding and copying a shared reference binding
  preserve that canonical referent Place; a moved mutable reference also takes
  over the active granting borrow
- explicit `ref`/`ref mut` match bindings for union and Result payloads carry
  active-variant Place provenance and a branch-scoped origin that cannot escape
  through a match result, outer assignment, returned aggregate or lambda
- storing a reference to local function storage into caller-owned field or index
  storage is rejected
- local aggregate variables that receive references to local function storage
  are marked, and returning them is rejected
- arena-backed references and slices carry an arena generation dependency
- using an arena-backed reference or slice after `Arena.Reset()` is rejected
- arena generations are merged conservatively across continuing `if`, `switch`
  and `match` branches
- arena generations are merged conservatively across `for` and `while` loops,
  including recorded `break` exits
- local reference origins are joined across continuing branches and across
  `for`/`while` entry, fallthrough, `continue`, and `break` edges
- a loop header is rechecked when its joined reference-origin state changes;
  identical origins retain one canonical Place, while differing known origins
  form a finite path-disjunctive Place set
- field, index and slice projections through a path-disjunctive reference are
  applied to every possible referent Place; reborrows register and validate a
  borrow for every possible owner root
- finite multi-origin sets contain at most 16 distinct Places. A missing origin
  or a larger set degrades to unknown provenance and reborrow is rejected,
  without runtime provenance metadata
- local struct and fixed-array values retain reference origins per canonical
  field/element path; nested literals, whole-value transfer, field assignment,
  constant indexing, dynamic-index joins, branches and loop fixed points all
  preserve or conservatively join those contained origin sets
- functions infer deterministic returned-reference summaries over symbolic
  parameters, projected parameter fields, multiple possible parameters, static
  method receivers and aggregate result paths; calls instantiate those summaries
  against the caller's concrete origin sets and retain the granting borrow

Not implemented yet:

- full escape analysis
- persisted/imported returned-reference metadata for separate compilation,
  function values, recursive summary cycles and all generic reference calls
- complete origins for references stored inside opaque foreign aggregates, plus
  symbolic interprocedural range relationships
- complete closure/reference escape validation

Initial limitation:

Escape diagnostics use path-specific origins for locally constructed and
summary-described structs/fixed arrays and a root-symbol fallback elsewhere.
Borrow analysis retains structured Places for direct aliases, aggregate fields,
elements and ordinary direct-call results. Statically known slice bounds are
normalized and composed through local aliases. Imported/opaque foreign values,
function values and unsupported recursive summary cycles remain conservative.
