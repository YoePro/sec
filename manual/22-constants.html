Constants

Sec does not use a const keyword. Immutable declarations use the let keyword, which creates an immutable binding — a value that cannot be reassigned after initialization.

Immutable Declarations

An immutable declaration binds a name to a value that cannot be changed:

let MaximumSize: int := 1024
let Name: string = "example"
let Pi: float64 = 3.14159

The right-hand side must be provided at the point of declaration. An immutable binding without an initializer is invalid.

Rule: Immutable declarations use let. Mutable declarations use let mut. There is no separate const keyword in Sec.

Constant Expressions

A constant expression is an expression whose value can be determined at compile time. Constant expressions are used in:

  • array length declarations
  • type contract ranges
  • default value clauses
  • enum variant values
  • compile-time parameter values

A constant expression must not allocate, depend on runtime state, or invoke non-constant functions.

Rule: An invalid constant operation invalidates the default, and the expression may not allocate or depend on runtime state.

Static Storage

static declares storage or members that belong to a type, function, or program rather than to one ordinary instance. static is a declaration modifier, not a type modifier.

Module-Level Static

Module-level bindings have static storage duration implicitly:

let Configuration: ApplicationConfiguration
let mut State: ApplicationState

These values exist for the lifetime defined for the module or program. The programmer may write static explicitly, but it is semantically redundant at module level:

static let Configuration: ApplicationConfiguration  // valid but redundant
Rule: The explicit static modifier at module level is accepted by the compiler but should be removed by the formatter as redundant.

Function-Local Static

A local declaration may use static to preserve one storage location across function calls:

fn NextID() int {
    static let mut value: int := 0
    value += 1
    return value
}

A static local variable:

  • is visible only inside the declaring function
  • is initialized once
  • retains its value between calls
  • is shared by all concurrent calls to the function
  • has static storage duration

It is not allocated separately for each invocation.

Rule: Mutable static storage accessed by tasks, threads, or mixed task/thread execution requires valid synchronization (e.g., Mutex[T], Atomic[T], or channel ownership transfer).

Static in Impl

Static type-associated storage belongs in impl:

type Counter struct {
    value: int
}

impl Counter {
    static let Maximum: int := 100
    static let mut Total: int := 0
}

Static declarations do not belong in the struct field list. Static members are not instance fields — they do not affect:

  • sizeof(Counter)
  • alignment of Counter
  • field offsets
  • ABI layout
  • object construction

Every Counter instance contains only its declared instance fields.

Static Members

Static members are accessed through the type name, not an instance:

// Valid
Counter.Total
Counter.Create()

// Invalid — must use type-qualified access
counter.Total  // error: static member must be accessed through type Counter
Rule: The compiler should require type-qualified access to make shared type-level state explicit.

Static Methods

A method that belongs to the type rather than an instance must be declared explicitly with static fn:

impl Counter {
    static fn Create() Counter {
        return Counter { value: 0 }
    }
}

Sec does not infer static membership merely because self is absent. A non-static method without a valid self parameter is invalid.

Rule: An explicit static fn is required for semantic clarity. A static method must not use self.

Static Properties

A property that belongs to a type must be declared explicitly:

impl Counter {
    static property Total: int {
        get { return total }
    }
}

Static properties follow the same access rules as static members — they are accessed through the type name.

Static Constraints

  • Static mutable storage requires valid synchronization when accessed concurrently.
  • Using a physical thread does not bypass static mutability or borrowing rules.
  • Lifetime validity of static storage does not imply concurrency safety.
  • Static members are not instance fields and do not affect object layout.

Sec v0.1 does not define thread-local storage syntax.
