# Correction 14 — spread validity and ownership facts are applied to the whole source instead of the accepted expansion

## Audit context

- Repository: `github.com/YoePro/sec`
- Repository baseline: `c515862`
- Audited: `2026-08-19`
- Primary rulebook: `rules/declarations/spread.md`
- Document revision: **2.0**
- Created: `2026-08-13`
- Last updated: `2026-08-14`

## Classification

Implementation bugs.

These are not language-rule changes.

Revision 2.0 defines spread as a contextual, non-consuming expansion. A spread
source is considered to supply values only after that spread is semantically
valid for the destination. Fixed-array call spread copies eligible elements; it
does not consume the source array merely because a selected callee parameter is
consuming.

Current Sema violates both rules in separate paths.

---

# Bug 1 — invalid move-only struct spread suppresses missing-field diagnostics

## Affected code

`internal/sema/analyzer.go`

In `inferStructLiteral()`:

```go
if field.Spread {
    spreadType, _ := a.inferExpression(field.Value)
    ...
    if !sameConcreteType(typ, spreadType) {
        ...
        continue
    }

    spreadSuppliesFields = true

    if !implicitlyCopyable(spreadType) {
        a.addErrorAtToken(
            field.Token,
            "cannot spread %s into %s; %s is not implicitly copyable",
            ...
        )
        continue
    }

    continue
}
```

The spread is marked as supplying all fields **before** copyability is validated.

Later:

```go
if !spreadSuppliesFields {
    // synthesize defaults and diagnose omitted NonDefaultable fields
}
```

Therefore a same-type but move-only spread can:

1. be rejected as an invalid spread; and
2. still suppress missing NonDefaultable-field diagnostics as though it had
   successfully supplied the target representation.

This contradicts both the rulebook and the current governance statement that
invalid spreads cannot suppress missing-field diagnostics.

## Required correction

Only a fully valid struct spread may contribute supplied fields.

Conceptually:

```text
resolve source
-> exact nominal type valid?
-> source implicitly copyable?
-> visibility/construction rules valid?
-> only then mark its fields as supplied
```

An invalid spread must contribute **zero** fields to later omitted-field/default
resolution.

# Bug 2 — fixed-array call spread into consuming parameters consumes the whole source array

## Affected code

`internal/sema/analyzer.go`

`callArgumentTypes()` expands a fixed-array spread by repeating the original
spread source expression:

```go
for i := int64(0); i < argType.ArrayLength; i++ {
    types = append(types, *argType.Element)
    expressions = append(expressions, spread.Value)
}
```

Thus:

```sec
Use(values...)
```

for `values: T[3]` becomes semantically represented as three argument slots, but
all three slots carry the AST expression:

```text
values
values
values
```

rather than element projections:

```text
values[0]
values[1]
values[2]
```

After overload resolution, `markMovedCallArguments()` processes those expanded
argument entries against the selected parameter modes.

For a consuming parameter:

```go
if param.Consuming {
    if a.markExplicitMoveSource(arg) {
        ...
    }
    continue
}
```

The `arg` is the entire `spread.Value`.

`markExplicitMoveSource(values)` therefore resolves the root array place and
marks the **whole source array unavailable**.

## Why this is wrong

`spread.md` revision 2.0 explicitly states:

- fixed-array call spread does not provide consuming spread;
- expanded indexed reads must be legal ordinary reads;
- in Sec 0.1 the elements must be implicitly copyable for the selected
  parameters;
- spread must not hide per-element moves;
- the source array must not be partially consumed merely by spreading it.

`functions.md` revision 2.0 states that a `->` parameter consumes the argument
value supplied to that parameter.

For spread of a copyable element, the argument value is the prepared copied
element value, not the containing source array.

Therefore:

```sec
fn Take(-> value: int) void { ... }

let values: int[2] := [1, 2]

TakePair(values...)
Use(values)
```

must not make `values` unavailable merely because the destination parameters are
consuming. The spread operation performs non-consuming indexed reads and the
callee consumes the prepared copies.

Move-only element arrays are already correctly rejected before this point.

## Required correction

Do not represent expanded call arguments solely as repeated references to the
whole spread source.

Sema needs resolved spread-argument facts that preserve at least:

- one source expression evaluated exactly once;
- source fixed-array identity/type;
- expansion count;
- element index for each expanded argument;
- effective argument type;
- copy operation selected for each element;
- selected destination parameter;
- ownership mode of the prepared argument value;
- source array remains available.

Ownership commit must apply to the prepared expanded values, not to the
container source.

A synthetic indexed-place representation may be used internally if it preserves
the rule that spread itself does not move elements out of the source.

Do not solve this by explicitly moving `values[i]`; consuming indexed extraction
is not spread semantics.

---

# Architectural requirement

Spread must be resolved before generic call ownership bookkeeping treats the
arguments as ordinary AST expressions.

A robust representation should distinguish:

```text
source expression
expanded argument slot
prepared argument value
source place affected by ownership commit
```

For ordinary arguments these can coincide.

For spread arguments they do not.

The same resolved facts should later feed Semantic IR rather than reconstructing
spread semantics in the backend.

# Governance reconciliation

The current `frontend.spread` entry lists as implemented:

```text
same-exact-type non-consuming struct spread ...
```

and:

```text
semantic struct defaults after explicit/spread resolution, with invalid spreads
unable to suppress missing NonDefaultable field diagnostics
```

The second statement is false for same-type non-copyable spread sources because
`spreadSuppliesFields` is set before the copyability check.

The entry also lists:

```text
fixed-array argument spread with exactly-once source analysis,
increasing-index expansion, and copyability checks
```

elsewhere in function governance.

Type/arity expansion and copyability checks exist, but post-resolution ownership
bookkeeping currently treats every expanded slot as the whole source
expression.

Narrow these claims until corrected.

The existing remaining Semantic-IR item is still valid, but these defects occur
already in frontend Sema and are therefore not merely missing lowering work.

# Required regression tests

## Struct spread

1. valid same-type copyable spread supplies NonDefaultable fields;
2. wrong-type spread does not suppress missing NonDefaultable-field diagnostics;
3. same-type move-only spread does not suppress missing NonDefaultable-field
   diagnostics;
4. invalid spread plus explicit supply of one field still diagnoses every other
   missing NonDefaultable field;
5. multiple spreads count only those that are semantically valid.

## Call spread ownership

6. spread of copyable fixed-array elements into ordinary by-value parameters
   leaves the source array available;
7. spread of copyable fixed-array elements into `->` consuming parameters leaves
   the source array available;
8. a mixed call with ordinary and consuming destination parameters still leaves
   the spread source available;
9. multiple consuming parameters do not repeatedly move the source array;
10. move-only element array spread remains rejected;
11. direct non-spread argument to a `->` parameter continues to consume the
    caller's argument;
12. source expression is analyzed/evaluated exactly once;
13. expanded element order remains increasing index order;
14. later failed argument analysis does not consume the spread source;
15. future Semantic IR records one source evaluation plus indexed expanded
    argument facts rather than N evaluations of the source.

## Applied 2026-08-23

Struct spread now supplies omitted fields only after exact-type and copyability
validation succeeds. Fixed-array call spread records prepared argument slots,
so consuming destinations consume the copied element value rather than the
source array. Focused regressions preserve direct consuming-call behavior and
reject move-only element expansion. Semantic IR projection facts remain tracked
as later integration work in `implementation-status.yaml`.
