Arrays

An array is a fixed-size, contiguous collection of elements of the same type. The length is part of the type and is known at compile time. Arrays own their storage inline — there is no hidden pointer, length field, or capacity field.

Type Syntax

Sec uses postfix array syntax:

T[N]

Examples:

byte[256]
int[4]
Packet[32]
Percent[10]

N is the number of elements and must be a non-negative compile-time integer.

Type Identity

Array length is part of the type. These are different types:

int[4]
int[5]

The element type also participates in identity:

int[4]
uint[4]
Rule: Two arrays are the same type only when both their element type and length match exactly.

Array Length

An array length must be a non-negative compile-time integer.

Valid:

int[0]
int[4]
byte[HeaderSize]

Invalid:

int[-1]
int[length]  // when length is a runtime value

The compiler rejects negative lengths, non-integer lengths, runtime-dependent lengths, arithmetic overflow, and lengths that cannot be represented by uint.

Zero-length arrays are valid.

Array Layout

An array owns N contiguous elements of type T. Its size is conceptually:

N * sizeof(T)

with checked layout arithmetic. Element alignment is the alignment of T. T must be a sized type.

A bare unsized type such as U[] cannot be an array element, but a reference to one can:

(ref byte[])[4]

This means an array of four shared byte slices.

Nested Arrays

Postfix dimensions are written from outermost to innermost:

int[3][4]

This means 3 arrays, each containing 4 int values. A matrix-like value may therefore be indexed as:

matrix[row][column]

Every dimension participates in type identity and layout checking.

Declarations

Examples:

let values: int[4] := [10, 20, 30, 40]
let mut buffer: byte[256]

An immutable array requires an initializer. A mutable fixed array may omit its initializer only when its element type is defaultable. Every element is then constructed from the element-type default before the binding becomes readable:

let mut values: int[4]  // equivalent to [0, 0, 0, 0]
Rule: Partially undefined element storage must never become a readable safe array.

Literals

Array literal syntax uses square brackets:

[expression, expression, expression]

A trailing comma is allowed:

[1, 2, 3,]

A target array type provides element type and required length:

let values: byte[3] := [1, 2, 3]
let percentages: Percent[2] := [10, 20]

Untyped literals are checked in the target element context.

When no target type exists, the compiler may infer the array type when:

  • the literal contains at least one element
  • every element resolves to one identical type
  • the length is the literal element count
let values := [10, 20, 30]  // inferred as int[3]

The compiler must not infer a common type through implicit conversion.

An empty array literal requires target context:

let empty: int[0] := []
Rule: The literal length must exactly match the target length. No spread, repetition, or dynamic-length array literal syntax is included in the initial implementation.

Default Initialization

Normal semantic default-initialization rules apply. A mutable fixed array may omit its initializer only when its element type is defaultable. Every element is then constructed from the element-type default.

A struct array recursively default-constructs each complete struct element. A zero-length array is defaultable without constructing an element.

Copy and Move

Array classification depends on its element type:

  • An array is trivially copyable when its element type is trivially copyable.
  • Copying an array copies every element and preserves the source.
  • Moving an array transfers ownership of every element and invalidates the source when the array type is move-only.

The compiler may warn about unusually large implicit array copies, but the warning must not change semantics.

Destruction

Array destruction destroys every still-initialized owned element in reverse index order:

N - 1, N - 2, ..., 0

A zero-length array has no element destruction. Moved array values are not destroyed by the previous owner.

Equality

Arrays support == and != when the element type supports equality. Comparison is element-by-element in increasing index order. Both operands must have the same array type, including the same length.

Function Parameters

Examples:

fn Sum(values: int[4]) int
fn Clear(values: ref mut byte[]) void

A by-value array parameter follows normal copy or move rules. A slice parameter borrows the source.

FFI

Arrays may cross an FFI boundary only when the complete array layout is ABI-compatible with the declared foreign ABI. Slices must not cross an FFI boundary directly.
